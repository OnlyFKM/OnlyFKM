# Cipherfeed

A dashboard that tracks publicly disclosed ransomware victims and groups —
functionally similar to public ransomware-leak trackers (e.g. ransom-db.com,
ransomware.live), built independently with its own design.

This is a defensive/threat-intelligence tool: it aggregates *already public*
victim disclosures (from group leak sites, as republished by tracking feeds)
for situational awareness and research. It does not access leak sites
directly, does not host stolen data, and does not facilitate contact with
threat actors.

## Features

- **Dashboard** — totals, 30-day trend, top groups/countries/sectors, timeline chart.
- **Victims** — searchable, filterable (group, country, sector), paginated table.
- **Groups** — profile per ransomware group with its listed victims.

## Data sources

By default the app ships with a **bundled demo dataset**
(`src/data/seed-*.json`, generated by `scripts/generate-seed.mjs`). Group
names reference publicly documented ransomware brands for realism; victim
organization names are fictional placeholders, not real companies.

To pull from a live public feed instead, set:

```bash
RANSOM_DATA_SOURCE=live
RANSOM_FEED_BASE_URL=https://api.ransomware.live/v2   # or another feed
```

See `src/lib/providers/liveFeedProvider.ts` — it was written without live
network access to the feed, so the endpoint paths/response shape are based
on publicly documented conventions and **should be verified against the
provider's current API** before relying on it. Every method falls back to
the demo dataset if a request fails, so the app keeps working either way.

To add a different provider, implement the `DataSource` interface in
`src/lib/types.ts` and select it in `src/lib/dataSource.ts`.

## Getting started

```bash
npm install
cp .env.example .env.local   # optional, only needed for a live feed
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).
